## 1 新增机检 `_dev/clock_probe.py`：图揭示完之后还动不动

用户的原始要求是"动画并行、不要单调"。`u` 只做揭示：图拼好就停在那里，20 秒的槽位里有 19 秒是一张静图。
批次 14 起逐张补的第二个时钟（`k.t` 歌曲时钟 / `lt` 图内已过时间）就是解药，但**这件事在图里看不出来**——
一张没有第二时钟的画和一张有第二时钟的画，静帧长得一样。

所以本批把它变成判据：

```
python _dev/clock_probe.py            # 59 行日程 × 在 u=1.0 下的三个时刻，有"无人认领的静帧"就 exit 1
python _dev/clock_probe.py --size 95x33
python _dev/clock_probe.py --selftest # 同样的参数画两遍，必须完全一致（证明差的格子不是噪声）
```

三个采样点取**该行自己的槽位**的 0.15 / 0.55 / 1.0，而不是固定窗口：一个两秒动一格的时钟
在 0.82 s 的槽位里就是没动，固定四秒窗口会把它算成"活的"。

第一次跑：**12 行静帧，其中 9 行没有理由**——`pane_everything_point`、`pane_curriculum`、
四个 AI pane、`pane_memory`。修完全部动起来，现在 `0 still with no reason recorded`。
静帧豁免表 `STILL_OK` 只留**本来就不该动**的：校园/人物照片版画（`landmark_*`、`class`、`knowledge`）
和左窗自己就是画面的那几行。

## 3 一个"图不动"背后其实是 bug：`head` 被覆盖

加报文点时先写了"沿消息行跑"的版本，`clock_probe` 报 `pane_exec_net moves 8`，但
`_dev/what_moves.py` 显示这 8 格**只有 2 格在图里**。原因：

```python
head = 3                              # 两条生命线顶端的行号
...
for ...:
    head = x_from + int(span * f)     # 同名变量被复用成"箭头的 x 坐标"
...
k.put(ax, k.by0 + head + int(...))    # 于是画到了 k.by0 + 100 多列的位置
```

`Screen.put` 对越界坐标**静默丢弃**，所以画面上什么都没有、`pane_probe` 全绿。
这是这套代码里第三次出现"越界写入被静默吃掉"，前两次分别是 CJK 按字裁剪和颜色元组。
修法是把循环里的变量改名 `tip`，并在注释里写明为什么不能再叫 `head`。

`_dev/what_moves.py`（新，非机检）就是为这类问题写的：给一行日程和两个时刻，
打印**哪些格子变了、在哪些行**——用来分辨"图在动"和"只有底部机件带在动"。

## 4 `check.cmd`：一条命令跑完全部机检

```
双击/命令行  project\check.cmd            六个探针，约一分钟
project\check.cmd --full                再加两种变体的全片扫描（各几分钟）
```

每个探针都改成**失败即非零退出**（`pane_probe`/`span_probe`/`trans_probe` 原本只打印、
永远 exit 0；`sweep_tui.py` 也是），`check.cmd` 只看退出码，最后打印
`RESULT: all checks passed` 或 `at least one check FAILED`，自身也返回 1。

| 探针 | 判据 |
|---|---|
| `pane_probe.py` | 51 pane × 6 尺寸：异常 / 越界 / 颜色元组形状 |
| `clock_probe.py` | 59 行：揭示完成后是否还在动 |
| `span_probe.py` | 26 个短槽位：第一帧是不是空的（例外具名记录） |
| `trans_probe.py --cells` | 5 种转场 × 5 个 q：整格不变量 |
| `density_probe.py` | 51 pane：全墨墙 / 全字块失败，条带只报 |
| `frame_probe.py` | 197×52 / 120×34 冷热帧时间，热帧超 41.7 ms 失败 |

两个坑，都写进了文件注释：

1. **`.cmd` 必须是纯 ASCII**，而且不只是编码问题：cmd.exe 按**字节偏移**找下一行，
   多字节字符会让它从**上一行的中间**接着解析，把注释里的词当命令执行。
   这次 `check.cmd` 的注释里引用了一句中文报错原文，于是开头冒出
   `'Run' is not recognized` / `'verdict' is not recognized` 等四条——检查全跑完了，
   噪声本身才是线索。改成全 ASCII 后消失（`非 ASCII 字节数 = 0`）。
2. **`frame_probe` 必须独占机器**：和别的构建并行跑时最差帧读到 48 ms（超预算），
   单独跑是 31 ms。第一次接进 `check.cmd` 就是这样误报的。

### 4.1 顺手抓出 `sweep_tui.py` 里一个一直没人看见的误报

给 `sweep_tui.py` 加上退出码之后，全片扫描报 `PROBLEMS: 0 crashes, 1 pane mismatches`：

```

```

不是回归，是**探针选点落在学院门窗口里**：`shot_moe_dense` 的中间时刻 136.30 s 落在
门的 131.9–136.9 五秒窗口内，那一刻整屏是**提问面板**，它盖住左栏，所以按"找窗口标题字样"
的判据当然找不到（标题本身也在批次 19 从 `dsh web` 改成了 `hangxiaotian`，
探针改为读 `tui_live.WINDOW_TITLE`）。改成先问门的状态：

```python
if G.window_open(t):
    flag = "   n/a (the college question is on screen)"
```

这条误报在**批次 11 就存在**（门是那批加的），只是 `sweep_tui.py` 从来不返回非零，
所有跑它的脚本都继续往下走——README 里"两种变体都 OK"说的是崩溃/越界/日程，不是这一项。
这正是"不能失败的检查等于没人跑的检查"的实例，也是本批把退出码补齐的直接理由。

## 5 顺手修掉：尾行时长 `10 ** 9`

`clock_probe` 打印每行时长，于是看到了 `span 999999806.54s`——日程表最后一行（193.46 s 的尾声校徽）
没有后继行，`end` 落到哨兵值 `10 ** 9`。后果不只是数字难看：`u = (t - at) / dur` **永远是 0**，
任何等 `u` 的内容在这 18 秒里永远不会出现。现在 `end = SONG_END = 212.0`
（`data/song.json` 里这首歌 211.913 s），尾行时长 18.54 s。
