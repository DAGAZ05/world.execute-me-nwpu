## 2 头像：两个错叠在一起，所以只看见上半张脸

### 2.1 `face` 裁切停在眼睛上

```python
CROPS["face"] = (0.20, 0.0, 0.80, 0.27)      # 即 y 0..175
```

这张插画（463×651）自己量出来的位置：**眼睛 y 155..185、嘴 ~228、下巴 240..244、衣领 ~250**。
所以 `0.27 × 651 = 175` **正好切在瞳孔中间**——头像是刘海 + 眉毛 + 眼睛，下面什么都没有。
批次 1 的记录里写着"`face` 60×21：只有脸"，那句话当时是照着这个裁切说的：在 60×21 的框里
上半张脸确实贴满边框，看起来"就是一张脸"。**看起来像脸不等于裁切是对的。**

现在的 `face` 是量出来的整头（`_dev/measure_art.py` 逐行打印墨迹范围）：

| 量到的 | 值 |
|---|---|
| 头发顶 | y=2 |
| 头最宽 | x 105..351（y 100..190） |
| 眼睛 | y 155..185 |
| 下巴收窄 | y 240..244 |
| 衣领出现 | y 250..256 |

→ `face = x 98..358, y 0..250`，紧贴墨迹后是 246×248，**长宽比 0.99**。这个近正方形是关键：
聊天头像的格子是 24×12 格 = 24×24 采样 = 正方形，裁切近正方形才能**满格**。

### 2.2 `avatar_rgb` 把行数翻了两倍

```python
grid, _w, _h = halfblock(expr, "face", cols, rows * 2)     # 旧
```

`halfblock` 内部已经为半块字符翻倍（`ur = min(cols/a, rows*2)`，一个 `▀` 格 = 上下两个采样），
所以再传 `rows * 2` 等于要 **2 倍行数**。两个后果：

- 宽裁切（旧 `face`，a=1.42）下它算出 8 行 → 12 行的框只用 8 行；
- 窄裁切下它会**多出**行（新裁切首测就是 13 行给 12 行的预算）。

也就是说 `tui_live` 注释里写的"school variant gets 12 rows (24x12 cells, 24x24 samples) because
航小天's face has to be **recognised**"**从来没有真正生效过**——一直是 8 行。
这正是"上半张脸"看起来那么扁的原因：8 行 × 横向 23 格，把额头拉宽了。

修完（`halfblock(..., rows)`）后逐尺寸满格：

```
24x12 -> 24 cells wide, 12 rows
16x8  -> 16 cells wide,  8 rows
12x6  -> 12 cells wide,  6 rows
10x5  -> 10 cells wide,  5 rows
 6x3  ->  6 cells wide,  3 rows
```

## 3 顺带修掉两处"测的不是程序做的事"

这两处不是本批目标，是查头像时撞出来的：

| 位置 | 问题 | 后果 |
|---|---|---|
| `_dev/frame_probe.py` | **没关 GC**，而玩家在 `tui_live.main` 里明确 `gc.disable()`（注释写着"gen-2 一次 20–27 ms 的洞"） | 全片最重的一帧（163.00 s 鱼雷炸屏）在不同运行里读 31 ms 或 46 ms，差的就是一次**玩家根本不做的**回收。接进 `check.cmd` 后第一次跑就因此报了 `OVER BUDGET` |
| `_dev/art_probe.py` | `sys.path` 插的是 `player/`，而 `mascot_glyphs.py` 在 `player/_tools/` | 这个脚本其实跑不起来，`_dev/out/` 里是**旧的一批 PNG**——所以裁切改了也没人看见 |

`frame_probe` 同时改成：**每帧取 `--reps`(默认 3) 次里的最小值**，并把单次最大值作为 `peak` 打出来。
理由是噪声只会**加**时间，最小值才是这帧的成本；单次最大值仍然打印，机器真慢照样看得见。

```
197x52    cold  mean   50.6 ms   worst  160.9 ms at t=200.00
197x52    warm  mean   17.9 ms   worst   31.9 ms at t=163.00   peak   32.6 ms  (3 pass(es), min kept)
```

关掉 GC 后 `peak` 与 `worst` 只差 0.7 ms（此前是 45.9 vs 31.3），这条检查从此不再抖。
