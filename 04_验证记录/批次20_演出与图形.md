## 1 最重要的发现：所有飞机/鱼/楼都是**带 alpha 的抠图**，而我们在二次抠图时把它们抠掉了

`school_fx._paper` 的抠背景是"量边框平均色 → 从边框泛洪"。对**带 alpha 通道的抠图**（航空照片、
魔鬼鱼、图书馆、校门、对话、鱼雷、航小天——占 60–80% 透明像素）来说：

- 边框环取到的就是那些**透明像素**，它们的 RGB 是 (0,0,0)；
- 于是 `bg=(3,3,5)`、`bright=False`、`tol=78`；
- 泛洪把"离黑 78 以内"的全部吃掉——**深色的魔鬼鱼身体首当其冲**，然后是飞机的深色蒙皮；
- 活下来的只有主体的浅色部分。

这就是"魔鬼鱼…我没看出来"的真正原因，也解释了飞机为什么一直像一抹灰。修法一句话：

```python
alpha = im.getchannel("A")
if alpha.getextrema()[0] < 250:          # 自带抠图：alpha 就是 key
    return im.crop(alpha.getbbox()) if crop else im
```

**顺带证明了它影响面有多大**：`对话`（74.7% 透明）也一直被抠坏——批次 20 的
`t0185_50_对话之手.png` 里，两只手是**第一次真正完整地出现**（此前只有几块碎片）。
`魔鬼鱼_旧的抠图错误.png` 是旧结果，`t0055_60_魔鬼鱼_放大.png` 是新的。

性能也顺带好了：抠图不再对每个 sprite 做泛洪，热帧最差值 31.9 → **26.2 ms**。

而这句话的主语本来就是学校（"第一架小型无人机 · 总师摇篮"是学校的成就）。

### 运-20 掠空（`lowpass`）

```python
near = sin(u·π)                                   # 两端 0、正中 1
size = max(16, int(cols * peak * (0.34 + 0.66 * near**0.7)))   # peak=0.66 → 正中 130 格
x = (cols + w)·u − w                              # 横向扫过
yy = rows·y + (0.5 − u)·rows·0.20                 # 斜的，不是轨道
```

"占据全屏 2/3"取的是**宽度**的 2/3（197 列 → 130 格）。飞机照片本身 1.5:1，130 格宽对应 41 行高，
其中主体占 22 行——加上冲击波、尘、抖动，正中那一帧就是"从头顶压过去"。

冲击效果分四层，都是 `u` 的纯函数（可 seek）：

1. **环**：以机身为中心向外扩的椭圆（`CELL_ASPECT` 换算，所以看着是圆的），亮度随离开正中衰减；
2. **冲击线**：整幅宽度一条水平线，在飞机自己的高度上；
3. **尘**：贴地一串 `░`，只在正中附近；
4. **整屏抖动**：新增 `school_fx.SHOCKS` + `shock(t)`，由 `tui_live.fx_shake` 取用
   （`max(原片自己的触发, 变体的冲击)`）。不复刻第二份"抖几行"的代码，`--variant original` 走不到这段。

## 3 魔鬼鱼：尺寸随形状 + 摇摆

两个错都在 `fly`：

- **行数是调用方写死的**（`rows_n=8`/`12`），而 90/(8×2.1)=5.4 的横条去装 1.69:1 的照片，
  `sprite` 只能上下裁掉一半——**翅膀就是这么没的**。现在 `rows_n=0` 表示"按这张图自己的形状算行数"
  （`_aspect`），飞机们仍旧显式给行数（对它们来说上下的天空是可丢的）。
- **没有波浪**。新增 `_undulate()`：每一列按 `sin(speed·t − c/λ·2π) × |c−中心|/半宽` 上下平移，
  振幅在身体中线为 0、在翼尖最大——蝠鲼就是这么游的。用户原话"应该扰动摇摆移动"。

## 4 何尊：用了用户给的 SVG，并且为它写了一个小 SVG 光栅器

`参考及想法/何尊.svg`（8.9 KB，1600×900，纯描边路径 + 一个镜像组）复制进 `assets/校园标识物/`，
由新的 `player/_tools/school_svg.py` 在运行时画成位图（`lru_cache`），再走既有的字符化管线。
不装 `cairosvg`（环境里没有，且要 C 库）：这个文件只用到 `M L H V C S Q T Z`、`circle`、
`translate/scale/matrix/rotate`，两百行读得下，遇到 `A`（弧）会记进 `UNSUPPORTED` 并**出声**，
而不是悄悄画错。

三个坑，都是"看不见但决定成败"的：

1. **矩阵合成写反了**。`translate(1600 0) scale(-1 1)` 一开始算成 `x' = −x − 1600`，
   墨迹范围变成 −2160..1115；`render` 按**墨迹**定尺寸，于是这张图被光栅化成 420×86 的细条
   （长宽比 4.9，而画本身是 0.94）。
2. **衬底**。描边 SVG 画在透明底上，RGB 全 0 —— 那是"23 对 0"的对比度，Sobel 几乎什么都看不到，
   出来就是四十来个散点（用户看到的"效果较差"）。改成**画在纸上**（23 对 255）后每个笔画都是满对比边。
3. **阈值治不了细节**。满对比之后，从 26 到 120 的任何阈值都留下 **58%** 的格子：这幅画的纹饰比一个
   字符格还小，所以"有没有线穿过这一格"和"这一格里有东西"用阈值分不开。最后走的是**alpha 的边界**：
   抠完背景后 alpha 是一个实心剪影，它的边界只有一条、方向唯一（亮度图上一条线的两侧梯度互相抵消，
   方向就成了噪声）。58% → **14%**，出来是器物轮廓：口沿、两侧扉棱、圈足。
   代价是**剪影内部的饕餮纹不画**——在 6 采样/格下那些纹饰小于承载它的字符，画上去就是糊。
   "认得出来是尊"比"忠实于纹理"重要。

两处用法都换了：`pane_landmark_hezun`（面板）和 7.30–9.60 的整屏 `plate`（**替掉**了原来的
`何尊_字符画.txt`，`GLYPH_EVENTS` 里只剩猫学长）。顺带修了 `_landmark` 里把 `CELL_ASPECT` 当 2 用
的尺寸公式——那 5% 的差正好把两侧扉棱裁掉。

## 5 为国铸剑：不是"太小"，是"被两个母题挤到 40%"

"微缩字符画太小了"查下去是构图问题：这块 pane 挂**两个**母题（`quantize` + `pixelsort`），
于是雕塑只分到 33 行里的 13 行。三件事：

1. **`MOTIF_SHARE`**：让 pane 自己声明保留比例，剑拿到 **0.68**（22 行）；
2. **`pixelsort` 移到"数据结构 · 排序"**（`school_courses.MOTIF`）——按亮度排序本来就是排序那一课的事，
   而且它占的是"一格一格的柱子"，不是需要辨认的照片；
3. **路线换成剪影**。试过三种：半色调（横向条纹）、描边（铁丝笼）、**剪影**。
   这座雕塑是**白石头拍在白背景上**（整幅只有约 70 级灰），所以：
   - 先 `_stretch()` 把不透明区域的 2%..98% 分位拉到满量程；
   - 再走新的 `SILHOUETTE` 路线：alpha 是实心的，一格一个 `█`，用石头自己的明度当色调。
   看一眼 `为国铸剑_面板.png`：横着的剑、两只手、头顶和肩膀都在，一眼能认。

## 6 图书馆：不是形状问题，是"太暗"

`flash(behind=True)` 固定把所有东西压到 0.42，而且 `dim` 参数**收下但没用**。现在 `dim` 真的接上了，
并新增 `contrast`；图书馆用 `dim=0.62, contrast=1.1`，尺寸 84×24 → 92×30，并且**加了字幕**
（"图书馆 · 灯还亮着"）。见 `t0194_60_图书馆.png`：玻璃幕墙的竖向分格已经能认出来。
