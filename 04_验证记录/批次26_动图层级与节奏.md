## 1 「打篮球面板不在最上层」——它是被画在了错误的一层

用户的原话值得照抄："我实际测了，我确定看不到打篮球面板，你观测到的可能和我不一样，在我这里打篮球面板
似乎不在最上层。"这句话里有一个技术判断，而且是对的：**面板画在了会话框的上一层**。

批次 24 把动图放进了左栏，但它是挂在 `school_fx.EVENTS` 上的普通事件，也就是在 `draw_body` **画完**
会话框之后、由整屏层再画一遍。于是它虽然盖住了会话框的文字，自己却又落在整屏层里，后面还要挨一遍
影片的后期：

| 后期 | 对一块"由空格组成的面板"做了什么 |
|---|---|
| `fx_reveal` | 切开时逐格用**上一帧**的缓冲替换（`s.buf = cur`），只有 `CLEAR` 矩形从新帧拷回 |
| `fx_trail` | 对**任何字符是空格**的格子写入上一帧的字符（`if buf[y][x][0] == " "`）|
| `fx_shake` | 按行整体旋转，行里的东西跟着走 |

一块 3300 格里 1333 格是空格的画板，就是一块有 1333 个"随便写"格子的画板。批次 25 我在这台机器上量到
"每一帧都有 2000+ 格面板在屏"，用户量到"看不到"——两边都没说谎：**画在缓冲区里**和**活到屏幕上是两件
事**，而 `_dev` 里所有探针（除了新写的这个）读的都是 `Screen.buf`。

修法是把层次关系摆正，而不是再加一层覆盖：

1. **面板归会话框那一层。** 事件表拆出一张 `WINDOW_EVENTS`，由 `tui_live.draw_body` 在画完会话框内容
   之后、用**它自己算出的矩形**调用（`school_panels.school_window_fx` → `school_fx.window_fx`）。矩形是
   参数传进去的，不在 `school_fx` 里重算，也不会读到过期或退化的 `LEFT_BOX`。
2. **面板里没有空格。** 底纹和画面里透明的地方都写 `█`（纸的颜色本身），所以 `fx_trail` 那条
   "字符是空格就写回去"的规则在面板里**一格也找不到**。实测（`_dev/live_screen_probe.py`，把播放器自己
   吐出的 ANSI 重新解码成屏幕）：框内 3332 格里 **3325 格有字形**，改动前只有 1999 格。
3. **`_dev/panel_probe.py`（新）** 逐帧走完整个窗口，量框里有多少格是纸色底：现在 19 个采样帧**全部**
   有 2000+ 格（`0 with the panel missing`），而在我把事件挪层之前，它是 23/23 全灭。

出图：`t0063_00_打篮球面板197x52.png` / `..._120x34.png`；终端解码见 `终端解码_打篮球在屏.txt`。
**另外**：批次 25 修的"第一帧把时钟跳掉 8 秒"（`last` 写在预热之前）也是一部分原因——窗口开头那几秒
在旧代码里根本没画。

**15 秒里有 5.5 秒是最后一行**（`layers=1` 一直挂到 125.33 的 铸剑），而那三句歌词
（`Erase all the pointless fragments` / `Then maybe, then maybe` / `You won't leave me so disheartened`）
讲的都不是毕业雕塑。现在的日程：

```
110.40  memory x2      1.58s   Though you have left
111.98  memory x3      0.91s   You have left
112.89  memory x4      0.86s   You have left
113.75  memory x5      1.00s   You have left
114.75  memory x6      1.15s   You have left
115.90  pane_isolation 2.05s   You have left me in isolation      <- 新
117.95  memory x1      1.86s   If I can, if I can
119.81  pane_fragments 5.52s   Erase all the pointless fragments   <- 新
```

MEMORY 从 15 秒降到 7.4 秒，**单行最长 1.86 秒**；空出来的两段各有一张新图：

- **`pane_isolation`**：一整片点阵，一格一格灭掉，中间留一个点在呼吸（`u` 决定灭到哪，所以 seek 与顺序
  播放一致）。正落在影片自己的 `shot_isolation` 上，左窗那一秒也正好在打
  `process 41827 (senior) has exited` / `reaping orphaned children ... 1 left`。
- **`pane_fragments`**：网格被一个游标一行行删掉，剩最后四格不删；正落在 `shot_erase` 上。
  游标**扫的是整片网格、包括已经删掉的格子**——这不是随便定的：`_dev/clock_probe.py` 是拿
  `u` 固定在 0.15 / 0.55 / 1.0 三个点采样的，游标若只在"还没删的格子"里走，在 u=1 时它就没有位置可动，
  那一行会被判成静帧。第一版就是这样挂的。

顺带把 `pane_memory` 的单层情形补上呼吸（`0.84 + 0.16|sin|`）：一层的时候没有"下一层"可走，`x1` 那一行
原本是彻底的静帧（`clock_probe` 会抓）。

两张新图都过了 `pane_probe`（56 panes × 6 尺寸 0 异常）、`clock_probe`（77 行 0 静帧无理由）、
`density_probe`（0 failing）。出图 `t0116_60_孤立_新pane.png`、`t0121_50_碎片_新pane.png`。

## 3 图书馆放在左下角

`flash` 新增 `x` 锚点（`0.0` 左 / `0.5` 中 / `1.0` 右），图书馆改成 `x=0.0, y=0.78`：贴着左边缘，

## 4 校门放大至超出屏幕

`fill` 现在允许大于 1，并且**锚点不再被夹到 0**（`x0 = int((cols - w) * x)`）：比屏幕大的图片要仍然
**以屏幕为中心**，不然"超出屏幕"就变成"偏到一边"。开头那次走进校门定为 `fill=1.45`，197×52 下终点是
**285×90**（屏幕是 197×52），四边都被裁掉——所以看到的是门柱、横梁和门洞的一部分，而不是一张门的照片
（出图 `t0002_90_校门超出屏幕.png`）。`zoom=0.20` 不变：整个 2.7 秒都在长大，前慢后快。

## 6 飞机、魔鬼鱼加白框

`sprite(..., outline)`：在图形的墨迹外面加一圈**白色轮廓**，一格的宽度，字符按墨迹在哪一侧选
（墨在上用 `▀`、在下用 `▄`、左右用 `▌`/`▐`、两边都有用 `█`），所以画出来是**轮廓**而不是一个方框。
它是**编进 sprite**（进 sprite 缓存）而不是每帧再扫一遍：130×41 的飞机是 5300 格，每帧再算一次就是
41.7 ms 预算里的 10 ms，而这圈线从来不变。`OUTLINED` 名单：`y20 / j20 / z20 / arj21 / manta / torpedo`
——"哪些图要白边"是**图**的属性，不是调用点的属性。

出图：`t0012_00_运20白框.png`、`t0055_90_魔鬼鱼白框.png`、`t0059_60_歼20白框.png`。
