## 2 飞机提亮

`paste` 的亮度坡度是 `colour * dim * (LIFT + SPAN * level)`，`LIFT` 就是一张照片的中间调出来有多亮，
也就是"这东西在 `(4,7,15)` 的底上看得见吗"。原来所有 sprite 共用 `0.72 / 0.42`；现在飞机与魔鬼鱼
（`fly` / `dive` / `sweep` / `lowpass` 四条路径）用 `AIRCRAFT_LIFT / AIRCRAFT_SPAN = 0.98 / 0.55`：
中间调 **+36%**，亮部略微压到 255，机身与背景分开（出图 `t0012_15`、`t0055_90`、`t0059_60`、`t0050_20`）。
作为背景的几张照片（校门、图书馆、对话的手）保持低的一对——把它们提亮会和自己上面的文字打架。

## 3 两个被 `except` 吞掉的异常（这一批真正的发现）

`school_fx.draw` 的每个事件都包在 `try/except Exception: pass` 里，于是**画不出来的事件是静默的**。
这一批在验证提亮时正好撞上两个：

1. **`paste(fast=True)` 里引用了 `BG`**，而 `school_fx` 里没有这个名字（`BG` 是 `tui_live` 的）。
   批次 27 加 fast 路径之后，**运-20 整帧画不出来**。更糟的是我当时的"性能测量"（60.4 → 18.9 ms）
   量的就是"什么都不画的帧"，而我据以判断效果的那张 PNG 是加 fast **之前**渲染的——所以自己和用户
   看到的不是同一个东西。现在用 `FRAME_BG = (4, 7, 15)`（并注明它等于 `tui_live.BG`）。

2. **`lowpass` 的冲击环、冲击线、地面尘用了 `_mix`**，而 `school_fx` 里同样没有 `_mix`。
   也就是说运-20 的"掠空冲击效果"——用户从批次 20 起就要的那个——**从来没有画出来过**，屏上一直只有
   飞机本体。用户两次说"视觉冲击还是不够"，看的就是这个。现在定义了 `_mix`（并写明它是
   `school_courses._mix` 的等价物：这三个颜色是字面量，不是要跟着主题走的 UI 灰）。

**结构性修复**：`draw` 的 `except` 现在**每个事件最多打印一次**警告（`_BROKEN` 集合，避免 24 fps 刷屏）：

```python
        except Exception as exc:
            if fn not in _BROKEN:
                _BROKEN.add(fn)
                print(f"warning: school_fx event {fn.__name__} failed ({exc})", file=sys.stderr, ...)
```

自查用的做法也记在这里：把事件表逐条在几个 u 上跑一遍并收集异常（见下面的"事件自检"），
比看静帧可靠——`check.cmd` 里的 `sweep_tui` 只跑两种变体、不逐事件报告。

```
$ python -c "...每事件 mid/f=0.1,0.5,0.9，收集异常..."
events that raise: {}          # 修前：{'lowpass': "NameError: name '_mix' is not defined"}
```
