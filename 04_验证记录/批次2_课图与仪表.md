## 5. `pane_memory(layers)` 已接通，1→6 层逐个看过

### 5.1 加的是一条**参数通道**，不是特例

`pane_memory` 从一开始就有 `layers` 关键字，缺的是"日程表怎么把数告诉图"这条路。
现在这条路的形状是：

```
school_panels.LANDMARK_ROWS  的某一行   args=dict(layers=6)
        ↓  school_entry()  把它放进 entry["pane_args"]
tui_live.draw_body        把它交给 SP_scene_pane(args=...)
        ↓
school_panels.draw_scene_pane(args=...)
        ↓
school_scenes.draw_pane(args=...)   fn(..., **args)
        ↓
pane_memory(..., layers=6)
```

`draw_pane` 里那个 `except TypeError` 是有意的：**日程表的标注是可选的**，
任何一个 pane 都必须能在没有参数的情况下照常画出来，一个多余的 keyword 不该让整帧崩掉。

### 5.2 层数是**几何衰减 + 位移随层增长**

```
level = 1.0                (layer 0)
level = 0.42 ** layer      (其余各层，下限 0.12)
off   = layer * 2          （像素级位移，层数越多摊得越开）
```

选几何衰减而不是线性，是因为雕塑的照片就是这样：第二层 MEMORY 还读得清，第四层几乎没有了。
线性衰减会让四层一样亮，那就不是"叠印"而是"重影"。

### 5.4 顺带修掉的一个真错

接线时发现 `school_entry` 把 `end` 夹在**原片镜头的结束时间**上，而原片的 EXECUTION 镜头是跟着音乐
切的、和这个变体的课程 pane 无关。有的 pane 因此算出**负的时长**（如 `110.40 → 1.00`）。
画面不受影响（`_Kit` 会把 `u` 夹到 0..1），但页脚和任何按时长推理的地方都是错的。
现在 `end` 直接取日程表那一行自己的结束时间。
