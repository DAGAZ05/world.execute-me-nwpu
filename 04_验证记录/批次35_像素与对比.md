## 2 双色半块：每格两个颜色位（本批最大的一处）

### 2.1 之前是什么

`sprite()` 每格采上下两个点，却**只留一个亮度标量**（`school_fx.py` 旧 `:274-275`）：

```python
k = 2 * r if top is not None else 2 * r + 1
row.append(("\u2580" if top is not None else SHADE[1], max(top or 0, bot or 0), P[c, k]))
```

下半格的 RGB 被丢掉，`paste` 把背景恒定成 `FRAME_BG`。**终端每格本来有前景+背景两个颜色位，
这条路只用了一个**——而项目自己的老路线（`tui_live.py:1751-1756`，鲸鱼头像的半块）两个都在用。
后果：所有照片退化成**横向色带**，航小天全身、校徽、两只手、图书馆都认不出主体。

### 2.2 改成了什么

`sprite()` 的单元格由三元组 `(ch, level, rgb)` 变成四元组 **`(ch, level, fg_top, bg_bottom)`**，
三种情况分别处理：

| 情况 | 字符 | 前景 | 背景 |
|---|---|---|---|
| 只有上半格有墨 | `▀` | 上半色 | 帧底色 |
| 只有下半格有墨 | **`▄`** | 下半色 | 帧底色 |
| 上下都有墨 | `▀` | 上半色 | **下半色** |

`paste()` 两条路径（`fast=True` 直写 buffer / 慢路径走 `Screen.put`）都写 `(ch, fg, bg)`，
慢路径把斜坡提成**每格一个标量**（两半共用），所以第二个颜色**不额外花时间**。

实测（`mascot` 65×44）：**1641 个格里 1552 格带上下半格颜色**。

### 2.3 `░` → `▄`（三处同病）

「只有下半格有墨」原来画 `SHADE[1]` = `░`：25% 覆盖率、**中灰**，而且 `school_scenes.py:927`
还额外乘了 0.7 亮度。改成 `▄`（50% 覆盖率、纯前景色）后，**所有图像的下缘对比度翻倍**——
而下缘正是剪影轮廓的大部分。

三处：`school_fx.sprite`、`school_scenes.py:927`、`school_sculpture.halfblock`。

> `_outline()` 里 `▄▌▐` 本来是**对**的，但 `OUTLINED = ()` 让整段成了死代码。本批没动它
> （用户已否决白框），但指出它现在与新四元组兼容（第四个字段填 `None`）。

## 3 对比拉伸：`LIFT/SPAN` 重解（A 方案）

`LIFT, SPAN = 0.72, 0.42` → **`0.30, 0.92`**；`AIRCRAFT_*` 由 `0.98, 0.55` → **`0.62, 0.94`**。

理由写进了代码注释，这里复述一遍关键的一句：
**`LIFT` 是"最暗的墨落在哪"，不是"把暗部抬多高"。** 0.72 意味着照片的黑只能到自身颜色的 72%，
全片**没有东西能到黑**——这就是"发灰"在数字上的样子。当初这么写有真实理由（飞机是暗底上的暗物），
但那个理由只对**剪影**成立，而双色半块已经接走了一半的活（下半格有了自己的颜色而不是帧底黑）。
所以照片拿到真正的黑，飞机保留抬高的地板。

`flash()` 的 `behind` **复合乘法**同时修掉（`school_fx.py` 旧 `:656`）：

```python
paste(s, cells, x0, y0, dim=dim * (0.42 if behind else 1.0) * fade)   # 旧
paste(s, cells, x0, y0, dim=(dim if dim > 0.0 else (0.42 if behind else 1.0)) * fade)   # 新
```

图书馆事件传 `dim=0.62, behind=True`，旧算式实际生效 **0.62 × 0.42 = 0.2604**——而紧挨着的注释
（`:605-608`）正在论证"0.62 而不是 0.42"。**注释推理的那个数不是代码用的那个数**，而且方向正是
用户当初投诉的方向（"图书馆我都没看出来"）。现在显式传的 `dim` 优先。

> 这条与批次 31 审计的"F3 转场搬错半屏"同类：**修了，但没修到用户抱怨的那个量上**。

## 5 抖动：Bayer 4×4 → 8×8，并修掉幅度

旧算式 `v + b * DITHER / n_lev`，`b ∈ ±0.46875`、`DITHER=0.5`、`n_lev=4`
→ 在 v 的 0..1 域里扰动 **±0.0586**；而**一级 = 0.25**，所以实际是 **0.234 级**，
注释却写"half is the textbook setting"（半级）。**抖动开着，但基本看不见。**

现在：`BAYER8`（8×8 矩阵）+ `v + b * DITHER * 2.0 / n_lev`，`DITHER` 的语义回到
**"允许挪动几级"**，0.5 = 半级，与注释一致。

`school_sculpture.halfblock`（对话/校徽/memory 三条地标图）原来**完全没有抖动**，
本批补上同一个 8×8 矩阵——它的五级量化正是那几张图色带的来源。两条路都是 `lru_cache`，
**每帧代价为 0**。
