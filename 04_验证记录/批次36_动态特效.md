# 批次 36 · 动态特效：转场对齐节拍、补三处缓动、修三处静默缺陷

用户四条方向的第二条：**增强动态特效**。本批做的是特效审计里**零代价或负代价**的那一批——
改常量、改索引、删死代码、给已有效果补缓动。**没有新增任何一个每帧 ms 级的特效**，
那部分（亮度脉冲、扫描线滚动）留到确认帧预算之后。

## 1 转场对齐到节拍（本批最核心的一处）

```python
TRANS_DUR = 0.42   # 旧：注释写 "a little over half a beat at 130 BPM"
TRANS_DUR = FP.BEAT  # 新：0.4615 s = 恰好 1.000 拍
```

**旧注释的算术是错的**：`0.42 / 0.461538 = 0.910`，是 **0.91 拍**，不是"半个多拍"（半拍 = 0.2308 s）。
这个错误从批次 9 起就在，同一句话抄在 `04_验证记录/批次9_转场.md` 里，**两处都错**。

切点是全片**唯一**"画面本来就该跟着音乐"的地方，所以这个常量该是音乐值而不是毫秒数。
实测确认：`TRANS_DUR / 0.461538 = 1.000`。

### 1.1 顺带：两条被截断的转场不再派发

`pane_gauge_attention`（159.66–160.06）与 `pane_gauge_fem`（160.06–160.45）的 span 只有 **0.395 s**，
比转场还短——`q` **永远到不了 1.0**，画面还在明显地移一半就被下一行覆盖。

现在 `_cuts()` 对 `span < TRANS_DUR` 的行**不派转场**：一个走不完的转场比一个硬切更难看。
实测 **79 行里跳掉 4 行**，剩 75 个切点（比审计预估的 2 行多 2 行，因为 `TRANS_DUR` 从 0.42 涨到了 0.4615）。

## 2 `_box()`：不再猜分栏宽度（D4，批次 31 F3 的残余）

批次 32 教会了 `_box` 看 `SWAP_AT`（换边），但**宽度仍是猜的**：

```python
return 1, 2, max(2, int(cols * 0.54)), rows - 3    # 197 列下 = 106，而 pane 实际到 97 就结束了
```

于是 02:16.9 之后的每一次转场都**多伸 8–9 列进会话窗**，搬的是会话窗而不是它该搬的图。

改法：让 `tui_live.draw_body` 像发布 `LEFT_BOX` / `BAND_BOX` 那样发布 **`PANE_BOX`**，
`_box()` 读它。实测同一帧：

| 来源 | 返回 |
|---|---|
| 旧算式（`int(cols*0.54)`） | `(1, 2, 106, 49)` |
| 新（读布局） | `(1, 2, 97, 49)` |

回退保留着——影片自己的全屏镜次（`shot_collapse` / `shot_flood`）不走 `draw_body`，那些帧仍需一个估计值。

## 3 补三处缺失的缓动

审计实测：`slide` / `zoom` / `skew` / `shatter` 都有缓动，**`page` 是纯线性**，`flash` 的非 zoom 分支、
`emerge`、`plate` 也没有。

| 处 | 旧 | 新 |
|---|---|---|
| `page` | `fx = cols-1 - (cols-1+peel) * q` | `... * (1 - (1-q)²)`，与另外三个转场同一形状 |
| `flash` 非 zoom | `z = min(1.0, u * 3.2)` | `z = min(1.0, u * 3.2) ** 0.75` |
| `emerge` | `grow = min(1.0, u * 1.5)` | `grow = min(1.0, u * 1.5) ** 0.8` |
| `plate` | `shown = int(ch * min(1.0, u * 1.6))` | `... * min(1.0, u * 1.6) ** 0.75` |

`flash` 那一条影响最大：**15 个整屏事件里有 9 个是 `flash`**，所以"匀速滑出一个矩形"
是全片出现次数最多的运动，而它以前恰好是唯一没有缓动的那个。

## 5 `window_fx` 的静默异常（D2）

`window_fx`（篮球面板那一层）用裸 `except: pass`，而同一个文件里 `draw` 早已改成
**每个坏事件打印一次**（`_BROKEN`）——那个机制正是"运-20 整帧消失一整批"换来的。

同一个模块里两套标准本身就是隐患，而窗口层恰恰是用户**已经报过两次**的那一处
（"航小天打篮球动图完全不见了"）。现在它照 `draw` 的样式打印一次。

## 8 本批**没有**做的（刻意）

特效审计里**唯一需要每帧 ms 级代价**的两项，本批不碰：

| 项 | 为什么缓做 |
|---|---|
| **亮度脉冲**（`FP.pulse` 驱动的全屏曝光呼吸） | 暗角是**画进每格 fg** 的（`put` 里预先乘好），所以"改 dim 场"不能让已画好的帧变亮——真实代价是**重绘那些格**，估算 4–6 ms/帧。而峰值已经到 42.7 ms（3 遍取最小），必须先有分项计时工具 |
| **扫描线滚动** | 同上：`_dim_field` 重算约 2–3 ms，且要重绘才可见 |

**为什么要先有工具**：现有工具链里 `_dev/fx_profile.py` 只量 `school_fx.draw` 整体，
**够不着 `tui_live` 的后期通道**（`fx_reveal` / `fx_trail` / `fx_shake` / `transition` 无分项计时）。
审计已给出手法（`_dev/_invariant_trace.py:71-80` 的 monkey-patch 挂钩 + `frame_probe.py:88-102` 的计时骨架），
下一步先补这个探针，再决定脉冲与扫描线的幅度。

其余待做（按收益/代价）：

- **`pane_curriculum` 136.90–147.52 的 10.62 s** —— 全片最长的无事件段，且**不在** `clock_probe` 的豁免表里。
  补"扫描高光 + 逐格写入光标"约 200–600 格 = 0.2–0.5 ms，是下一批最该做的一处。
- 79 行日程里 **61 行无事件、26 个空窗 ≥ 2 s**（`pane_motif_bessel` 5.49 s、`pane_fragments` 5.52 s、
  `pane_motif_sine` 5.15 s 等）。补"薄噪声纸"约 120 格 = 0.1 ms。
- `SHOCKS` 只有一个窗（11.85–12.45）；运-20 是"视觉冲击不够"被投诉三次的事件，可扩窗 + 补一个衰减尾窗
  （`fx_shake` 每行一次切片，几乎零代价）。
- `stand` 的跳跃峰值只有 4 格 / 44 格高 ≈ 9%，偏保守。
- `fx_trail` 的 `TRAIL = 0.42` 可随 `FP.pulse` 微调（残影在拍上更黏）。
- `page` 仍走逐格 `put`（5400 格 = 4.57 ms，全曲最慢帧所在），可换直写 buffer（−4 ms）。
