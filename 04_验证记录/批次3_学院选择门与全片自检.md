## 1. 学院选择门装好了

`school_gate.py` 的状态机，四个状态：

| 状态 | 含义 |
|---|---|
| `waiting` | 歌停在那里，问题在屏幕上，等一个键 |
| `rejected` | 按了一个不是 `s` 的键：显示原因，**问题继续挂着** |
| `answered` | 按了 `s`：进入软件学院，歌继续 |
| `assumed` | **拖动进度条跳过了门**，没有人按键 |

**`assumed` 和 `answered` 必须分开**，这是把"门"做成状态机而不是一个布尔值的原因：
一个是学生说了"软件"，另一个是观众拖了进度条、从头到尾没回答过。两者落到同一个专业
（`DEFAULT_MAJOR = "s"`），因为另一种做法是让影片卡在一个没人看得见的问题上，
那会破坏 seek 安全性（skill §1.1）。但它**不假装问题被问过**：`asked` 保持 False，
窗口不会声称自己收到过回答。

### 1.1 时钟怎么停

停的是**时钟**，不是"顺便把声音关掉"：歌的时钟就是影片的时钟，所以卡住时钟就卡住了歌。
`pv_audio` 只在**开始卡住的那一帧**暂停一次（`STATE["held"]` 记住），不是每帧调一次设备。

### 1.2 页脚会说为什么

`⏸ 等你回答：软件学院 按 s`，以及状态字从 `PLAYING` 换成 `等你回答`。
一个观众看到进度条不动而没有解释，只会以为播放器坏了。

### 1.3 出图

`t0133_00.png`：左窗从上到下是 `TypeError: make_sense() got an unexpected argument 'god'`
→ `[非法参数]` → 「接下来这一段不是我说了算。问你一个问题。」→ **问题 + 八个学院选项**
（`s` 是实心点，其余是空心点）→ `请按 s 继续` → `等你回答`；页脚同步。

## 2. 接门的时候抓到的三个错

| # | 严重度 | 问题 | 修法 |
|---|---|---|---|
| F1 | **HIGH** | **问题被印了两遍**。`school_dialogue` 里 131.90 那条自己写了问题，而门的实时块也印一次 —— 聊天窗是累积的，于是同一句话上下各出现一次。 | 问题**只归门所有**（只有门知道它有没有被回答）；对话里那条改成"接下来这一段不是我说了算。问你一个问题。"作为铺垫 |
| F2 | **HIGH** | **按错一次键，门就再也答不了了**。`armed()` 只认 `waiting`，按 `a` 之后状态变成 `rejected`，紧接着按 `s` 被吞掉 —— 门变成一次机会，误触一个键就把影片放过去。 | `armed()` 把 `rejected` 也算作 armed。**这个错是直接驱动状态机（`_dev/_check_gate.py`）发现的，不是看出来的** |
| F3 | MEDIUM | **窗口在 130.0 s（门还没到）就挂着问题**。`window()` 只要 `t > GATE_AT` 就附加门的块，而门的状态是模块级的，于是从 02:11.9 到全片结束都挂着。 | 改用 `gate.holds(t)`：只有**正在卡住**的时候才附加 |
| F4 | LOW | 页脚打印 `PLAYING` 的同时打印 `⏸ 等你回答`。 | 状态字也跟门走 |

顺带修掉一处：原来滑动条把 `t` 直接改掉，门的 `tick(seeking=True)` 会把播放头**拽回
02:11.9** —— 也就是"你拖到哪里它就把你拉回哪里"，这不是 seek 该有的行为。现在
`reached(t)` 只判断"这一跳是不是跳过了整段门"（`t >= GATE_UNTIL`），是的话 `assume()`，
播放头留在观众要求的位置。

## 3. 全片自检（`sweep_tui.py`）

给 `sweep_tui.py` 加了变体感知。变体必须在**导入 `tui_live` 之前**决定
（那一步就选好了模块），所以走环境变量：

```
python _tools\sweep_tui.py                             原片
set PV_VARIANT=school && python _tools\sweep_tui.py    西工大版
```

报告的形状跟着变体走，因为其中两节讲的是原片的故事（`--render auto` 的高潮区间、
"她的窗格"普查）。把那些数照印一遍，等于满屏"一部没在放的片子"的真话，比少印更糟。

### 3.1 它一上来就抓到两个零长度的 pane

第一次跑西工大版，`non-positive spans` 列出两条：

```
{'at': 0.03, 'name': 'pane_power_on', 'end': 0.03}
{'at': 1.33, 'name': 'pane_protection', 'end': 0.03}
```

原因：`pane_landmark_crest` 和 `pane_power_on` **都想要 0.03 s**。
两行同一时刻就是重叠，后一行拿到零长跨度 —— **`pane_power_on` 从头到尾没有被画过一次**，
而在屏幕上看不出来（右栏留着原片自己的面板，看起来像是有意为之）。

修法：开机段从六个 pane 砍到四个，`crest(0.03) → power_on(1.33) → protection(3.58) → class(5.16)`。
这也顺带把顺序改对了 —— 歌词里"put on protection"在"object creation"**之前**，
原来的表把它们排反了。`pane_pieces` 因此失去自己的时段，它保留在
`PANE_BY_NAME` 里（画法是完整的，探头也过），并在文档字符串里注明"当前未排期"。
