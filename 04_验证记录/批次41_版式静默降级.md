# 批次 41 · 把"dump 出来看"变成机器检查（版式静默降级）

批次 40 的结尾留了一条自我批评：**那批最有价值的产出不是五处修正，而是"dump 出来看"这个动作**——
`c_ds_algo` 的三栏并排从未生效，这件事既不在任何探针的输出里，也不在逐张核验的审计报告里，
只在把整屏打出来读一遍时暴露。本批把它变成检查。

---

## 1 这一类缺陷的形状

`c_ds_algo` 的写法是**先问版式、再按答案分支**：

```python
cols = k.columns(3, [10, 7, 9], mins=[40, 26, 30])
if len(cols) == 3:
    ...并排...
# 否则落到堆叠
```

`_Kit.columns` 在不满足 `sum(need) + 2*(n-1) <= bw` 时**返回 `[]`**，而调用方写的 `if len(cols) == 3`
是"拿不到就自己退让"。于是当 `mins` 之和比 pane 体还宽时，**并排分支静默地一次都不执行**，
而 pane 照常渲染、照常在动、照常在框内——**每一个现有探针都是绿的**：

| 探针 | 为什么看不见 |
|---|---|
| `pane_probe` | 它只查异常、越界、颜色形状。三栏退化成堆叠，三者都正常 |
| `clock_probe` | 堆叠版一样在动（甚至更"空"，`_live` 元件仍在走） |
| `density_probe` | 堆叠版的墨量与补丁数也在阈值内 |
| `row_probe` | 它只查 pane 跨了几句歌词，与版式无关 |
| `span_probe` | 第一帧有内容，通过 |

**这就是"声明与实现不一致"里最难查的一种**：代码没写错，字面意思与行为不一致，
而唯一的症状是"画面没有作者以为的那么满"。

---

## 2 探针：`_dev/layout_probe.py`

做法：把 `school_courses._Kit` 换成一个子类，**记录每一次 `columns()` / `bands()` 被要了什么、
实际返回了几段**，凡 `len(out) < n` 就是一次静默降级。按电影真实使用的三档尺寸跑：
`95x30`（197×52 窗口下的 pane 体）、`57x24`（120×34 下）、`113x36`。

```
python _dev\layout_probe.py
python _dev\layout_probe.py --sizes 95x30,113x36
```

### 2.1 覆盖范围（如实说明）

全项目只有 **10 处** layout 调用，分布在 **6 个函数**里：

| 文件 | 行 | 函数 | 要什么 |
|---|---|---|---|
| `school_courses.py` | 630 | `c_oop` | `columns(2, mins=[40,34])` |
| | 793 | `c_os` | `columns(3, mins=[24,30,24])`（需 ≥7 行） |
| | 1241 | `c_industrial` | `bands(2)` ×2 |
| | 1599 | `c_ds_algo` | `columns(3, mins=[34,22,30])` |
| | 1608 | `c_ds_algo` | `bands(3/2/1)`（大小相关） |
| `school_scenes.py` | 1129 | `pane_everything_point` | `columns(3, mins=[28,30,24])`（需 `bw≥60`） |
| | 1290 | `pane_exchange` | `columns(4, mins=[20,22,22,18])`（需 `bw≥90`） |
| | 1297 | `pane_exchange` | `columns(3, mins=[26,26,26])`（需 `bw≥78`） |

实测记录到的调用数：**95x30 → 6 次、57x24 → 1 次、113x36 → 6 次**。

**所以它覆盖的是"声明了多栏/分段版式的 6 个 pane"，不是全部 75 个。** 其余 pane 是单区绘制，
不存在降级这个概念，也就没有可检查的东西。这一点写在探针的 docstring 里，免得后来者以为它是全局的。

## 3 一个从未失败过的探针不算探针

这是我前几批一直用来判断别人工具的话，所以本批对**自己新写的这个**也照办：**故意把缺陷放回去，
看它会不会响**。

```python
# 临时把 c_ds_algo 的下限改回旧值
cols = k.columns(3, [10, 7, 9], mins=[40, 26, 30])
```

结果：

```
=== 95x30: 1 degraded layout call(s) ===
  pane_exec_ds               asked columns(3) -> got 0
FAIL: 1 pane(s) believe they have a layout they do not have
```

**抓到了，而且是它该抓的那一个**（`c_ds_algo` 就是 `pane_exec_ds` 的绘制函数），退出码 1。
随后把 `[34,22,30]` 恢复，探针回到 PASS。这次"先证伪再相信"的过程写在这里，
是因为**上一批正是因为一个探针从不失败而漏掉了整类缺陷**。

## 4 我自己的探针有两个 bug，都会造成假通过

写这个探针时我连错两次，两处都值得留档，因为它们正是本项目反复出现的同一类错误。

### 4.1 `CO._Kit` 递归：每个 pane 都崩

```python
class Watched(CO._Kit):                      # 子类
    def columns(self, n, weights=None, mins=None):
        out = CO._Kit.columns(self, n, weights, mins)    # ← 但 CO._Kit 已经是 Watched
```

我只把 `CO._Kit` 替换成 `Watched`，却在子类里通过 **`CO._Kit`** 调"父类"方法——
那已经是我自己，于是**每一次调用都是自己调自己**。跑出来的是一屏
`maximum recursion depth exceeded`，每个 pane 都画不出来。

修法：**在替换之前把真正的基类抓到一个名字里**（`_BASE = CO._Kit`），子类内部一律走 `_BASE`。

### 4.2 抛出的异常被静默跳过 —— 于是"全炸"看起来像"全对"

更严重的一个。第一版把异常接住并打印，然后继续：

```
pane_motif_stardiff        raised: maximum recursion depth exceeded
pane_motif_quantize        raised: maximum recursion depth exceeded
...（每一个 pane 都是这行）
=== 113x36: no pane asked for a layout it did not get (0 layout call(s)) ===
PASS: every declared layout is the layout that runs
```

**每个 pane 都崩了，探针却打印 PASS**——因为"画不出来"意味着没有 layout 调用被记录，
而空集合当然"没有降级"。这正是我这几批在别人代码里修的**构造性绿灯**
（`check_coverage` 对 82 行永远返回 `[]`、`glyph_probe` 把加载失败报成满分），
我自己又犯了一次。

修法：绘制抛异常的 pane **单独计数并计入失败**，报告里明写"无法绘制的 pane 是失败，不是缺席"。

### 4.3 附带修掉：报错定位不到 pane

第一版的报告写的是 `? asked columns(3) -> got 0`——因为 `Watched` 的子实例没有 pane 名。
用一个模块级一格列表 `CURRENT = ["?"]`（`tui_live` 用同样的手法），在 `__init__` 里取，
现在的报错是 `pane_exec_ds asked columns(3) -> got 0`，可直接定位。

## 7 遗留

1. **探针止于"版式是否如期返回"，不检查"返回的版式好不好看"**。三栏各占多少宽、
   是否某一栏只有 3 列可读，仍要靠 `density_probe` 与出图看。
2. **`bands` 的降级不算缺陷**：`c_ds_algo` 的 `bands(3, [5,3,3]) if h >= 24 else ...`
   是**主动**按高度选版式，不是失败。本批的判据（`len(out) < n` 即降级）对它是纯报告，
   当前三档尺寸下它没有触发。
3. 前两批列的遗留仍在：`_cuts()` 的索引空间、`FILES` 两字前缀兜底、`sweep`/`approach` 死代码、
   `EXEC_PANES`（16 项）与 `02b §4.1`「十二门课」叙述的差异未在文档里说明。
4. **仍需你拍板的一条设计冲突**（批次 37 提出、37/38/39/40 各记一次仍未定）：
   02b §4.6 要求 `pane_love_class`（184.33–187.97）「全片唯一允许静止」，
   而 `clock_probe` 要求每个 pane 都有运动；现在代码选了后者（把 `t` 传给 `hearts9` 触发心跳）。
