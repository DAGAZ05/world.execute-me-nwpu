## 1 `c_os`：进程表的 %CPU 之和是抬头那行的三倍

同一屏上印着两处 CPU：

```
%Cpu(s):  6.2 us,  1.1 sy, 92.7 id        ← 抬头：忙 7.3%
  PID USER      PR  NI  %CPU  %MEM  STAT  COMMAND
 4100 root      20   0   0.4  0.3  ...    ← 每行 0.4 + 4.0*|sin|
```

每行是 `cpu = 0.4 + 4.0 * abs(sin(lt * 1.1 + i))`，8 行相加实测 **21.4 % – 25.5 %**
（另用独立计算复核：上限 8×4.4 = 35.2）。**进程表声称的 CPU 是它上面那行的三倍。**

这一屏的 docstring 写得很清楚："this is the machine's own output, numbers move, **nothing is
asserted**"——而一张与自己抬头矛盾的进程表，恰恰是在断言一件假事。

**修法**：忙的那份切成两半给前两行（user / sys），并让抖动**守恒**。

### 1.1 第一次修**没修对**，被探针抓住了

第一版写成 `cpu = own * (0.82 + 0.18 * abs(sin(...)))` —— 看起来是"每行在自己那份里呼吸"，
但它在**同一时刻把每一行都缩小**，于是总和必然偏低：

```
header says 7.3% busy;  the 8 rows sum to 6.7%
```

**这与原缺陷是同一类，只是小一点。** 探针报 FAIL，改成守恒式：

```python
ratio = 0.85 + 0.05 * math.sin(lt * 1.1)      # 忙的时间如何在 user/system 之间分
share = [busy * ratio, busy * (1.0 - ratio)]  # 两半恒等于 1
```

实测：**抬头 7.3%，8 行相加 7.3%**。

> 这条值得单独记：**"因四舍五入而少一点"和"差三倍"是同一种缺陷**，后者一眼能看出，
> 前者要靠量。

## 2 `_os_states`：进程状态机的转移标注指错了边

五个状态 `新建 → 就绪 → 运行 → 阻塞 → 终止` 按序竖排，四条转移标注按序贴在它们下方：

```python
trans = ("fork", "调度", "时间片到", "I/O 请求")     # 旧
```

于是一条边被命名为 `运行 → 阻塞` = **"时间片到"**，下一条 `阻塞 → 终止` = **"I/O 请求"**。
两处都错，而且错在这门课的第一道题上：

- **时间片到**是把 `运行` 打回 **`就绪`**，不是打到 `阻塞`；
- **I/O 请求**是把 `运行` 打到 `阻塞`（I/O 完成再回 `就绪`），**不是把进程送出到 `终止`**；
- `终止` 由"终止/退出"到达，与 I/O 无关。

**修法**：前向边改为 `fork / 调度 / I/O 请求 / 终止`，并补一行脚注把两条回边写清楚：
`阻塞不占 CPU；时间片到→就绪，I/O 完成→就绪`。

### 2.1 我在这里把 `k` 写成了 `d`

`_os_states(d, lt)` 的形参是 `d`，我补脚注时顺手写了 `k.put(...)` → `NameError: name 'k' is not
defined`。**被我自己刚写的验证探针当场打出来**（它直接调 `draw_scene_pane` 绘制整屏）。

这与 `pane_probe` 存在的意义是同一件事：**改完必须真的跑一次那条绘制路径**。

## 3 `g_burndown`：图例画了一个字形，图上画的是另一个

```
k.put(k.bx1 - 16, k.by0, "ideal ─  actual ●")     # 旧：图例说理想线是 ─
k.put(x, y, "·", ...)                             # 实际：理想线是 ·（U+00B7）
```

这是这批里最小的一处——**也正因为小，它活了整条命**：没有人会盯着一张燃尽图的图例看。
但图例的全部功能就是"告诉你哪个字形是哪个量"，字形对不上，图例就不成立。

改成 `ideal ·  actual ●`，与实画一致。

## 4 `g_assembly`：抬头写着 41 个零件，实画 6 个框，其中两个还叠着

两件事同时错：

| | 实测 |
|---|---|
| 抬头 `BOM 41 parts` | 循环画 `n = max(3, min(6, (w-10)//12))` = **6** 个框 |
| 框的位置（w=95, u=1.0） | `P5: 83..89`、`P6: 89..95` —— **第 89 列重叠** |

重叠的根因是 `cx = min(cx + sep, k.bx1 - 6)`：**越界的框被夹到同一列上**，
于是"爆炸视图"里两个零件插在彼此内部——而爆炸视图的全部意义就是零件**分开**。

**修法**：零件数由循环决定（上限提到 8，`BOM {n} parts` 写实际值），步距由宽度解出，
分离量上限取"剩余空间"。

实测（8 种宽度 × 5 个 `u` 共 40 组）：**重叠 0 处**。例如 w=95、u=1.0：

```
P1@6  P2@16  P3@27  P4@38  P5@49  P6@60  P7@71
```
