## 1 `c_c`：越界红格是**死代码**——这一课的要害没上过屏

`c_c` 的 docstring：这门课"唯一真正令人不安的想法"是 **`*p++` 不知道数组在哪里结束**，
所以画面应该是"一排格子 + 一个移动的指针 + **一个越过末尾、仍然可以写进去的红格**"。

```python
step = int(lt * 2.4) % (n + 3)      # 指针走到 n+2 都在循环
over = step >= n
for i in range(n):                  # ← 但只画 i < n
    col = RED if (over and i == step) else ...
```

`over` 为真时 `step ∈ {n, n+1, n+2}`，而循环只产出 `i < n` —— **`i == step` 永不成立，
红格一次都没画过**。屏幕上只剩指针指向一个空位置和一行警告文字。

**修法**：把越界的三格**画进画面**（越界越远越暗），并在数组真正结束处加一条边界线，
那是"语言不检查"的那条线。

实测：**11/80 帧**出现红格（17 个指针位置里 3 个越界位）。

## 2 `c_db`：B+ 树的叶键里**没有**它在查的那个值

同一屏上两处：

```
Index Cond: (id = 41827)          ← 计划说要找 41827
B+ leaf  0  137  274  ...  1507   ← 叶键是 i*137，最大 1507
```

**索引扫描在找一个索引里没有的值**，而"高亮的那片叶"也就没有理由被高亮。
一门课如果讲的是 B+ 树，一棵不含查询键的 B+ 树讲的是反面。

**修法**（三处一起）：

- 叶键**以 41827 为中心**生成（`41827 + (i-mid)*137`），要查的键就在其中；
- **内部节点放真正的分隔键**：每组叶的首键（B+ 树的内部节点存的就是子树最小键）；
  原来是一个空的 2 槽框配 4 个子节点；
- 根框按分组数画（4 槽），持有 41827 的那片叶用琥珀色标出。

### 2.1 我第一次修**自己把键覆盖了**

为了标出命中的叶，我先在 `xx+4` 加了一个 `◀`——**那正好是 5 位键的第 5 位**，
于是屏上出现的是 `4182◀`，查询值被指向它的箭头擦掉了。**探针把那一行读回来才发现**
（`leaf row: ... 4182741964 ...` 里少一个数字）。去掉标记，只用颜色。

## 3 `dijkstra_cracks`：**不是 Dijkstra**

```python
for i in range(3):                     # 三个候选，取最便宜的
    nx, ny = x + 1, y + (i - 1)
    if i == 0 or cost(nx, ny) < cost(x + 1, y):
        y = ny
```

两处错，而且互相掩护：

- **`i == 0` 是无条件的**——第一个候选根本没被比较就赢了；
- 比较的基准 `cost(x + 1, y)` 里的 `y` **已经被那个无条件分支改写**了，
  所以后两个候选是拿"移动后的起点"在比。一个"从不评估第一个邻居、其余邻居从漂移的基准去量"的贪心；
- 更根本的是：**它只有一步前瞻**。标题写 `Dijkstra 裂纹`、字幕说裂纹是"最便宜的那条路"，
  而贪心下降离最短路线可以任意远。

**修法**：对同一个确定性代价场跑**真 Dijkstra**（优先队列，弹出即定型），
用 `lru_cache` 按 `(w, h)` **只算一次**——代价场是坐标的纯函数，路径在整屏期间不变，
所以整个母题的每帧代价只是一次切片。

实测（新路径 vs 复现的旧贪心）：

| 尺寸 | Dijkstra 代价 | 旧贪心代价 |
|---|---|---|
| w=95 h=15 | **2071** | 3342 |
| w=57 h=8 | **1316** | 2049 |
| w=113 h=20 | **2434** | 3962 |

**新路径稳定便宜约 38%**——这不是风格差别，是"最便宜的那条路"与"看起来像路的一条路"的差别。

> 附带确认：`dijkstra` 这个母题**没有被排进日程**（`MOTIF` 里注册了，但没有任何 pane 用它），
> 所以本批对它做的改动**不影响全片每帧耗时**。

## 4 `c_dl`：声称"沿同一张计算图回流"，画的是**一条曲线加斜杠**

docstring 写："红色的边是梯度沿着**同一张图**回流，蓝色的边把激活前向送过去。
把它们画在一张图上就是这门课的核心思想。" 而画面是：**一条 loss 曲线**，
"反向传播"是在曲线旁边偏移 ±1 行画 `\` 和 `/`。
**斜杠旁边的曲线不是计算图**，而"前向和反向是同一组边的两个方向"这件事**根本没上屏**。

**修法**：画两张、并且是两种不同的东西：

- 上三分之一：loss 曲线（监控一次训练长什么样）；
- 其余：**图**——5 个节点，前向箭头蓝色在上一行，反向箭头红色在**下面一行**、
  从右往左走，各边标 `∂L/∂W₂`、`∂L/∂a`、`∂L/∂W₁`、`∂L/∂x`。

两个方向**同时可见**，这才是"一张结构的两次遍历"，而不是两张图。

实测：**20 个节点角（5 节点 × 4）、前向箭头 4、反向箭头 4、梯度标注 8**。

## 5 DFD：同一个外部实体出现两次，**没有标记**

`c_software_engineering` 把 `教师` 这个外部实体画了两次：左侧（提交行）一次、
右侧（编译行）一次。**Yourdon/DeMarco 记法允许重复外部实体，但前提是重复的那次要标记出来**
（星号或斜线）——否则读者会数成两个人。

而这一屏自己的图例正在讲"记法要对"（"箭头上都有名字：没有名字的流向图叫流程图"），
所以一个未标记的重复是**同一类的错**。

**修法**：右侧那次改成 `教师*`，图例补上 `* 同一实体的重复出现`。

## 6 我自己的探针犯了三个错——两个是**假绿**

这部分比上面五处更值得记：**每一次都是"探针看起来在工作"**。

### 6.1 宽字符占位格让任何中文都搜不到（假绿）

DFD 的检查第一次跑出：

```
'教师' occurrences: 0 (of which 0 are marked as a repeat)
legend explains the mark: False
PASS: ...
```

**打印了 PASS。** 两个原因叠在一起：

1. `Screen.put` 在每个**双宽字符后写一个空占位格**。把一行按格拼成字符串时，
   `教` 和 `师` 之间夹着一个占位格，于是 `"教师"` 这个**子串永远匹配不到**——
   标签、图例，全都匹配不到。缓冲区里的格**不是**一个字符串。
2. 我的判据写的是"**多于 2 个且没有星标**才失败"。既然一个都没找到，
   条件为假——**"什么都没找到"被当成了通过**。

修法：拼字符串时**跳过空占位格**；并且把"找不到标签"本身判为**失败**
（探针看不见 ≠ 画面是对的）。

**同源问题还在 `math_probe` 里潜伏**：它的 `_text` 也是把空格子替换成空格，
所以**它任何一条中文子串检查都永远不会命中**。之所以一直没暴露，
是因为它此前的检查全是 ASCII（`class`、`DFD`、`ER`、`diag`）。已一并修掉。

### 6.2 `"" in "任何东西"` 恒为 True —— 让检查"没有图也通过"

为了验证 `c_dl`，我写的是：

```python
corners = sum(1 for ... if s.buf[y][x][0] in "\u250c\u2510\u2514\u2518")
```

同一个屏幕两种数法：

```
count_in    = 139     # ch in "┌┐└┘"
count_cells =  20     # 先滤掉 "" 和 " "，再判 in
```

**Python 里 `"" in "abc"` 是 True**，而缓冲区里到处是空占位格——
于是 119 个空格子被当成了方框角。

真实数是 **20**（5 个节点 × 4 个角），而我在 `math_probe` 里新写的这条检查
**即使一个节点都没画也会报非零**：`not corners` 永远不成立。
同一写法还在第 4 节的树节点定位里（`s.buf[yy][xx-1][0] in MARKERS`）——空占位格会被当成标记符。

全部改成"先要求字符非空，再判成员"。**这是本批最有价值的一条**：
它不改变任何画面，却让两条检查从"永远通过"变成真的会失败。

### 6.3 判据本身的量纲错了（假红）

红格的检查第一版要求 `r > 200`，而红格的颜色是 `_mix(RED, 0.45)` = **(114, 26, 21)**,
于是它把一个**已经画对了**的 pane 报成 `0/60`。改成"红色占优"（`r > 90 且 r > 2g 且 r > 2b`）
后是 11/80。

> 这是本项目的第 N 次同一个教训：**判据本身也要被验证**——
> 前有 `check_coverage` 的构造性绿灯、`glyph_probe` 把加载失败报满分、
> 批次 40 的探针"每个 pane 都崩却打印 PASS"。本批一次抓到三个。
> 区别是这次**它们在我的代码里**。
