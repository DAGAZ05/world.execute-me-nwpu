## 1 新工具：`_dev/stage_probe.py`

把帧管线按**名字**逐段包住（`_dev/_invariant_trace.py` 的手法），报告"最差的那一帧，时间花在哪一段"。
七个段：`draw_body` / `draw_flood` / `draw_collapse` / `draw_footer` / `school_fx.draw` /
`school_fx.transition` / `draw_lyrics` / `fx_apply`（含 `fx_reveal`、`fx_trail`、`fx_shake` 三个子段）/
`Screen.normalise` / `Screen.render_diff`。

两条规矩照抄 `frame_probe`，理由相同：**关掉 GC**（播放器关着），**热段取多轮最小值**（噪声只会加时间）。

### 1.1 它必须先修自己的一处盲区

第一版用 `frame_probe` 那 21 个采样点，跑出来**看不到任何转场开销**。查下去发现：

```
page cuts: [5.16, 12.47, 25.14, ...]
```

`page` 转场在 **5.16**，而采样点取的是 **5.00**——早 0.16 s，**没落在转场里**。
而转场只持续 `TRANS_DUR` = 一个拍（0.4615 s），21 个散点能撞进去的概率很低。

修法：**每个切场贡献一个采样点**，取它转场的中点（`at + dur/2`）。采样点 21 → **98**。

## 3 修法：大图版走 `paste` 的快路径

`school_fx.draw` 的 4.82 ms 里，主体是**两张走慢路径的大贴图**：
`library`（3232 格）与 `stand` 的全身像（2860 格），而慢路径是**逐格 `Screen.put`**——
一次方法调用 + `CLEAR` 区段查找 + 宽字符配对修复。

`paste(fast=True)` 是直写 buffer（**运-20 的 285×90 就是靠它从 60.4 ms 进预算的**），
而且它**内联了暗角**（`drow[x]`）、语义与慢路径一致。

```python
# flash：大图版自动快路径
paste(s, cells, x0, y0, dim=..., fast=(w * h >= 1500))
# stand：全身像
paste(s, cells, x, y, fast=(cw * chh >= 1500))
```

阈值 1500 格不是微优化：低于这个规模两条路测出来一样，而慢路径保留它的宽字符修复。

### 3.1 为什么敢跳过 `_unpair`

`fast=True` 会跳过 `_unpair`，而这正是**批次 27 那个"相当多的字符显示混乱"**的成因类别，
所以不能靠推理，必须量：`_dev/ansi_probe.py`（把播放器吐出的 ANSI 解码回屏幕、与缓冲区逐帧对比）。

```
5084 frame(s) compared at 197x52; 0 with at least one mismatch
```

**5084 帧、0 处不一致**——宽字符不变量没有被破坏。

### 3.2 效果（同一个工具前后各量一次，3 轮取最小）

| | 修前 | 修后 |
|---|---|---|
| 最差帧总时 | **41.9 / 51.0 ms** | **38.2 ms**（机检内 40.0） |
| 该帧的 `school_fx.draw` | 4.82 / 6.48 ms | **2.26 ms** |

从**超预算**回到预算内。

## 4 门禁本身的漏洞，也一并补了

这条比上面那 4 ms 更重要：**`_dev/frame_probe.py` 是 `check.cmd` 的性能门禁，
而它一直是绿的——因为它只采 21 个点，看不见转场帧。**

新增 `sample_times(with_cuts=True)`：在 21 点网格之外，**加上每一次切场转场的中点**
（21 → 98 点）。默认打开，`--no-cuts` 可退回旧网格。

修后门禁自己报出真相：

```
sampling 98 times (the grid plus the middle of every cut)
197x52  warm  mean 24.6 ms  worst 40.0 ms at t=193.69  peak 47.6 ms
budget 41.7 ms per frame (24 fps); 0 size(s) over it
```

> **一个采样不足的门禁与一个不会失败的门禁同样不可信**，这是本项目第五次遇到同一类问题
> （前四次：`check_coverage` 的构造性绿灯、`glyph_probe` 的假阳性、批次 40 探针"全崩却 PASS"、
> 批次 43 的 `"" in "任何字符"`）。区别是这次它在**性能**维度上，而且它掩盖的是一个真的超预算帧。

## 5 关于亮度脉冲与扫描线：本批**仍然没做**，现在有数字了

批次 36 缓做的两个效果，现在的定价依据是：

- 最差帧余量 = **1.7 ms**（40.0 vs 41.7）；
- 而 `render_diff` 已经占最差帧的 **15.74 ms**。亮度脉冲要改**全屏每格的 fg**，
  于是每一格都与上一帧不同 → **`render_diff` 从"只写改动格"退化成"写满整屏"**；
  暗角是画进 fg 的（`put` 里预先乘好），所以"改 dim 场"不能让已画好的帧变亮，**必须重绘**。

**结论：1.7 ms 的余量不足以承载一个全屏重写效果。** 要做，先得把 `render_diff` 的写出量降下来，
或者只在 pane 区（约 1/3 屏）做脉冲。这一条留给下一批，而且现在有工具可以给它定价。
