## 1. 最后两处还在用原片名字的地方

这是前几批剩下的唯一一件事的两半：**右栏和左窗都已经是西工大了，但屏幕中间那两条最响的
正文还不是。**"最响"是字面意思——一条紧跟时钟，一条占满聊天窗下面整条带子五秒钟。

| | 原来 | 现在 |
|---|---|---|
| 顶部章节条 | `00 / BOOT`、`01 / PRETRAIN`、…、`09 / WHALE_FALL` | `00 / 上电`、`01 / 初始化`、`02 / 定义`、`03 / 电与时间`、`04 / 副歌一`、`05 / 万物皆点`、`06 / 你走了`、`07 / 非法参数`、`08 / 处决`、`09 / 软工与爱` |
| 左窗下方自检带 | `power: 8x H800 online`、`pcie: link up x16`、`infiniband: 400 Gb/s`… | `power: USB 5V 0.48A`、`board: UNO R3 (ATmega328P)`、`clock: 16.000 MHz crystal ok`、`i2c: LCD1602 at 0x27`、`sensor: HC-SR04 trig/echo`、`[WARN] hc-sr04: echo floating, wire D3`… |

两者都是**纯数据**（一个 `(起止, 标签)`，一个 `(时刻, 状态, 文本)`），形状就是播放器已经在读的形状，
所以覆盖它们是两个名字而不是第二套绘制函数——`draw_boot_log` 只改了一行
（`B = SP if school else FP`），连 4 格状态牌、80 px 间隔、光标、`post n/14` 计数都照旧。

**章节时间取的是 `01_歌词分析.md` §1 的段落边界**，不是估的：00:29.28 是
"If I'm a set of point" 的起点，00:44.04 是 "Switch my current"，00:58.65 是第一次 "If I can"。
唯一例外是 00:16.00——那不是歌词而是第一段器乐空隙；原片自己的 `01 / PRETRAIN` 也从 16.0 开始，
因为那是开机行之后第一件真事发生的地方，两个版本都需要一个边界在那里。

### 1.1 自检带的内容为什么是 Arduino

原片打印的是一台 GPU 集群的 POST。这一版打印**这部片子真正在讲的那台机器**——
桌上的一块板子，上面挂着一个传感器和一块屏。节奏、状态牌、结尾那条 `WARN` 全都照原片
（`attachment_to_user: not in policy` 变成 `hc-sr04: echo floating, wire D3`，
也就是"板子还没接好"的实话版）。

## 2. 顺带补掉的一个真缺口：02:41 之后右栏是空的

接章节条的时候发现，右栏最后一块西工大 pane 停在 **161.51 s**，之后到全片结束
（02:41.5 → 03:31）回落成原片自己的面板。前几批的记录里我一直写着"全曲覆盖"，
**那是错的**——覆盖到 02:41 为止。修法是把 `02b` §4.3–4.6 点名的四个时刻做出来：

| 时刻 | 歌词 | pane | 画的是什么 |
|---|---|---|---|
| 162.23–169.61 | `If I can give them all the execution` → `Be your only execution` | `pane_converge` | **六张图并排 → 收成一张 UML 类图**。六张小图各自是一个记号（需求/DFD/ER/盒图/活动图/状态图），按 `u` 向中间收拢 |
| 169.61–176.96 | `If I can have you back` / `Though we are trapped` | `pane_backlog` | **Scrum 看板，"完成"那一列永远是空的**，卡片一直被推回左边 |
| 176.96–184.33 | `I've studied how to properly love` | `pane_knowledge` | **一条能力曲线**（不是课程列表），五个点：C / Java / OpenEuler / PGSQL / 反向传播，每点一个极小图形 |
| 184.33–193.46 | `the algebraic expression of lo-o-ove` | `pane_love_class` | `class Love` 放大铺满，**全片唯一不动的 pane** |

现在右栏从 00:03 到 03:13 全程有西工大的 pane，之后是尾声的校徽（193.46 起）。
`pane_love_class` 的文档字符串里写明了它为什么不动：`02b` §4.6 要的就是"别的都在动，这一张不动，
因为答案已经写完了"，所以它是这个变体里**唯一一个函数体里没有 `lt` 的 pane**。

## 3. 这一批抓到的错

| # | 严重度 | 问题 | 修法 |
|---|---|---|---|
| G1 | **HIGH** | **门的"正在等你回答"判定太宽**。`holds()` 只问 `t >= GATE_AT`，于是 02:11.9 之后**全片**都成立——在 02:50 那种早就回答过的帧上，窗口把问题又挂了一遍，页脚写着"等你回答"。 | 改成 `abs(t - GATE_AT) < 0.5`：**"正在卡住"是播放头在门口，不是播放头过了门口**。这是看出图看出来的 |
| G2 | **HIGH** | **`s.put()` 多传了一个参数**。四个新 pane 里写了 `s.put(x, y, text, fg, 1.0)`，而 `Screen.put` 的第五个参数是**背景色**。那个 `1.0` 进了缓冲区，一路走到 `render_diff` 才炸（`'float' object is not subscriptable`），离出错的地方隔了一层调用栈。 | 去掉那个参数。它原本想表达的是"亮一点"，而这个函数里没有这个参数 |
| G3 | MEDIUM | `pane_love_class` 的类框固定按八行画，在 7 行和 5 行的 pane 里把下面两行写到框外。 | 按 `h - 2` 截断行数 |
| G4 | LOW | `_landmark`、`pane_converge`、`pane_backlog`、`pane_knowledge`、`pane_love_class` 里的 `BLUE`/`AMBER`/`BOX_H`/`BOX_V`/`_mix`/`_ui` 是**模块级名字**，但只有 `school_scenes` 自己那套常量在模块级，课程那套在 `school_courses` 里——`pane_probe` 一次报出 14 个 `NameError`。 | 统一从 `school_courses` 取（`import school_courses as _C`），和 `pane_memory`、`_landmark` 已经用的方式一致 |

**G2 值得单独说一句**：`pane_probe` 没抓到它，因为它只检查"抛异常"和"墨写到框外"，
而这一次抛异常发生在**播放器自己的 `render_diff` 里**，不在 pane 里。
探头画完 pane 就直接读缓冲区，从不调用 `render_diff`。也就是说——
**机检有一个盲区：颜色元组的形状**。下一版探头应该顺手检查每个格子的
`fg`/`bg` 是不是三元组，那样 G2 这类错会在 pane 那一层就被抓住。

## 5. 收尾：把 G2 的盲区堵上，顺带修掉两个小项

### 5.1 `pane_probe` 现在检查颜色元组的形状（G2 的盲区）

`_bad_colours()`：逐格检查 `buf[y][x]` 是一个三元组、且它的 `fg`/`bg` 都是**整数三元组**。
这是那个"第五个参数传了 `1.0`"的错唯一能被抓住的地方——从 pane 的角度看它画得好好的
（没抛异常、每一格都在框内），**错在它写下去的东西的形状**。

**验证过它能抓**：把 `1.0` 注回 `pane_converge` 里一个确定会执行到的分支，
探头立刻在三种尺寸下报出来：

```
pane_converge()   118x11:COLOUR bg=1.0 in (' ', (140, 150, 167), 1.0)   118x9:COLOUR ...   60x7:COLOUR ...
3 problem(s) across 41 panes x 4 sizes
```

然后撤掉注入，回到 `0 problem(s)`。**一条检查在它对已知错误报警之前，不算存在。**

### 5.2 `pane_converge` 的两个问题

接上面的验证时顺手看了这个 pane 的两个状态，两处都不对：

| 问题 | 现象 | 修法 |
|---|---|---|
| 收拢态的类框**没有角** | 四条边画出来了，但四个角是 `─`/`│` 而不是 `┌┐└┘`，看起来像一个没画完的方框 | 边画完之后单独把四个角补上 |
| 六张图的**顺序和形状** | 检查后确认是对的：`u=0.05` 时六张各自完整（118 列下每张 39 列宽 × 4 行高），`u=0.99` 时收成一个类框 | 无需修 |

第二行是"检查之后**没有**找到问题"，写在这里是因为它的价值和不写一样：
我原先怀疑那六张图是重叠着画坏的，看了两个状态的输出才知道它们是对的。

### 5.3 校徽（E2）：由"糊"变成"只是一块小方章"

批次 2 的 E2 记录的是"在 118×11 的栏里只有约 6 行，看不清是徽记"。接第 3 项时顺手查了
为什么，答案是 `_landmark` 的 `max_rows=9` 先把行数压到 9，后面那一步按源图长宽比算列数时
又用这个**已经被压过的行数**去反推列数，于是方形图被拉成了一条。改成按源图长宽比算
"**最多能占多少行**"，不预先压行数之后，校徽按它自己的宽度（约 26 列）画出来，
圆形轮廓和里面的飞行器剪影都成立。

**它仍然只是一个 26×13 的小印章，而不是一个"看得清纹样"的徽记**——这不是缺陷而是约束：
`pane_power_on` 的走线区只让出 11 行，而徽记要认得出纹样至少需要 20 行。
E2 从"糊成一团"降级为"小但成立"，**我不认为它值得为它去抢别的 pane 的行数**，
所以标注为"已改善、按现状接受"。

### 5.4 ops 跑马灯密度（E4）

**未修，且我决定不改。** 原来的记录是"每行重复同一个词，密度偏高"。
重看之后发现那是**设计**而不是缺陷：跑马灯滚的是这个 pane 自己在做的事
（`FUSE / ESD / STRAP` 或 `VERIFY / SHA256 / MISMATCH`），
和原片自己的 ops 面板滚 `CONVERGE / EMBED / PCA / TSNE_STEP` 是同一种东西。
原片的 ops 也重复到你看不见它在说什么——它是一台机器的活动指示，不是一封信。
改成"不重复"反而会让它看起来像在讲某件事，而它不该讲任何事。

**这条从待办里划掉，记在这里作为一次有意的"不改"。**
