| 项 | 值 |
|---|---|
| 文件 | `assets/航小天.png`（复制自 `参考及想法/航小天.png`） |
| 格式 | 真 PNG，RGBA，463×651 |

**这一条很重要**：立绘已经自带 alpha，所以**不需要、也不许**做"近白即背景"的抠图——航小天的航天服本身就是白的，那种做法会把衣服挖空。

## 2. 三种画法各自的结果（看图定的）

| 画法 | 算法 | 结论 |
|---|---|---|
| **glyph** | Sobel 边缘 → 方向字符 `\|-/` + 内部亮度渐变 | **弃用**。463×651 的插画压到 60 列，眼镜、面罩、接缝、比耶的手全都是边，出来是一片纹理而不是一张脸 |
| **ramp** | 直接亮度 → ` .:-=+*#%@` | **弃用主用**。保留作故障/打字转场（原片 `glyph` 模式的语义位） |
| **halfblock** | 每格上下两个亮度样本，`▀` 的 fg/bg 上色 | **采用**。原片"蓝色清晰像"的算法，在这张图上明显最强 |

halfblock 在三个尺寸下都成立（已逐张看过）：

- `full` 37×26：完整小人，航天服、头盔、比耶、国旗章都认得出
- `bust` 57×26：头肩，脸、眼镜、发际线清楚 ← **窗口内大图用这个**
- `face` 60×21：只有脸，60 列时脸贴满边框
- **聊天头像**：`bust` 32×16 能认出是这个人；`face` 32×16 更像"一张脸"；**16×8 已经什么都看不出**

> **批次 19 修正**：上面这一行是在**错的 `face` 裁切**上看的，结论因此是错的。
> 当时的 `face` 是 `(0.20, 0.0, 0.80, 0.27)`，即 y 0..175——**正好停在眼睛（y 155..185）上**，
> 所以"只有脸"其实是"只有上半张脸"；再加上 `avatar_rgb` 把行数传成 `rows*2` 让 `halfblock`
> 又翻了一倍，24×12 的头像实际只画了 8 行。用户看到的就是"只截了上半张脸"。
> 现在 `face` 是量出来的整头 x 98..358 / y 0..250（`_dev/measure_art.py`），头像按 24×12 满格出图。
> 原始判断保留在上面，因为**"看起来像一张脸"本身不足以说明裁切是对的**——这条教训值得留着。

## 3. 表情：从一张图派生八个

原片有八张表情立绘，航小天只有一张，所以八个表情是**画上去的**：

- `face_overlay()` 在 `face_region()`（实测 x 106..351, y 128..272）上贴一张**脸部自身的拷贝**，再画眼睑、瞳孔、嘴
- 不是"用肤色椭圆盖住原脸"——那个做法试过两次，第一次是一张惨白色圆盘、第二次那块椭圆往上长，把刘海吃掉了，人物变成秃的。**拷贝区域而不是覆盖区域，整类失败就不存在了**

八个表情在 56×13 的框里已经能分辨（见证据图）：`normal` / `happy` / `serious` / `confused` / `worried` / `proud` / `shy` / `flat`。

## 4. 定的两个数字（都是量出来的，不是看出来的）

| 数字 | 值 | 怎么定的 |
|---|---|---|
| 瞳孔 | 左 (204, 165)、右 (260, 168) | 在头顶区做**暗色连通段扫描**（逐行印 x 上的暗段）：y 164..184 上有 x 150..172 与 x 233..264 两段，就是两个瞳仁；y 208..220 上有一条 x 231..295 的宽带，是嘴 |
| 脸区 | x 106..351、y 128..272 | 把框画到原图上截图看（`--boxes`），再按瞳孔位置微调 |

**教训（写在这里是为了别再犯）**：眼睛的位置用肉眼从插画上读，连着读错了三次（瞳孔落到了脸颊上、又落到了刘海上、又左右反了）。原因是眼镜——镜框让整张脸**看起来**关于另一个中心对称，左镜片比它里面的眼睛靠左得多。**量比看可靠。**
